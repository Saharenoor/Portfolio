Why Frontend + AI?

A short version of how I think about building software right now.

Systems before style

Before I touch a framework, I want to understand the structure underneath it. Building GitHub Lite from raw data structures taught me more about how real version control works than using Git ever did on its own — that habit carries into everything else I build.

Learning by shipping

I'd rather have five small, finished projects than one perfect idea that never left the whiteboard. Competitions, incubation, and internships have all pushed me to ship something real under a deadline — and that pressure is where I've learned the most.

AI as a layer, not a headline

My time working on AI-focused tasks at Softnexa showed me that the interesting part isn't the model — it's how carefully you wire it into a product a person actually uses. That's the direction I want to keep growing in: solid frontend and systems fundamentals, with AI layered in thoughtfully rather than bolted on.

Frontend + Backend + AI

How the three pieces actually connect in what I build.

One person, full loop

I don't like handing off "the backend" to someone else in my head — on projects like the appointment system, I design the interface a user sees and the role-based logic, data, and workflow behind it, so the two sides are built to fit each other from the start.

Backend as the backbone

The interface is what people see, but the backend is what makes it trustworthy — access control, data structure, and clean APIs. Working with the MERN stack and Odoo has taught me to treat that layer as seriously as anything on screen.

AI that talks to both ends

What I want to build next isn't AI bolted onto a UI — it's AI woven through the whole loop: an interface simple enough to use, a backend that feeds it the right data, and a model in the middle doing something genuinely useful with it.
